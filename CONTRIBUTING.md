# Contributing to KS Client

Use the source ZIP for the release you are testing. Follow [BUILDING.md](BUILDING.md) to verify the download, build it and run the relevant tests.

For a bug report, use the [KS Client feedback repository](https://github.com/epicjatekosok/KS-Client-Updates/issues) and include the client version, Windows version, steps to reproduce and the expected result. Remove personal information, account identifiers and session data from screenshots and logs. Report security issues through [SECURITY.md](SECURITY.md).

For code changes, send a focused patch against a named release and list the tests you ran. Keep installer, runtime and updater changes independently reviewable. Submit code you are entitled to license under the project's [MIT terms](LICENSE), and identify any third-party material with its license, origin and required notices.
